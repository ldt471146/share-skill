# GitHub 项目学习

围绕用户想学会的概念或功能，连接教程、实际代码与学习证据。版本定位、运行记录和教学程序是新增应用扩展；它们不是《如何阅读一本书》的原书规则。

## 开始当前任务

从对话和实际材料识别学习对象、目标、已学范围及环境；信息足够就继续。区分 Git/GitHub 操作教程、其他技术教程、库、应用与资料索引，按 [学习流程](workflows/learn.md) 执行。

用户仅要讲解或笔记时，从材料完成相应任务。用户已要求安装、练习或跑通时，检查相关命令与环境后执行必要步骤，不增加例行确认。

论文与实现的联合分析由同级 [research-reading](../research-reading/SKILL.md) 主导。若收到的是科研流程指定的实现子任务，只收集指定版本、功能路径或运行结果等实现证据，返回主导流程；不再次转交科研入口，也不代替它判断论文贡献与实验结论。

## 共享规则与安装关系

本技能与 `how-to-read-a-book`、`research-reading` 三个目录放在同一技能根目录，作为同一套件安装。原书规则和公共笔记规范由 `how-to-read-a-book` 单独维护；本流程在需要的阶段直接读取其文件，不调用它的 `SKILL.md` 或路由重新选择任务。

若同级目录或引用文件缺失，先检查已安装目录中是否存在对应文件，明确实际采用的路径。仍缺失时说明具体依赖未加载，继续已具备材料的事实读取与讲解，不声称应用了缺失规则；需要该依赖的原书归因、统一笔记规范或跨模块结论保留未完成状态。恢复套件应安装三个目录的同一发布版本。

## 当前任务的完成依据

按学习流程检查解释、用户要求的运行与练习。分别报告已读范围、实际运行结果和用户理解证据；缺少其中一类证据时不互相替代。

生成或核对笔记时，读取共享 [笔记规范](../how-to-read-a-book/references/note-contract.md)。解释方法来源、调整本技能或审查原书归因时，再读 [方法与适用边界](references/method-boundaries.md)。
