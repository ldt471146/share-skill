# 方法来源与适用边界

用于解释来源、维护本技能或检查规则归因。常规学习任务按流程执行，无需为背景说明加载本文件。

## 原书原则的有限迁移

共享 [原书规则](../../how-to-read-a-book/rules/analysis.md) 及 [检视规则](../../how-to-read-a-book/rules/inspection.md) 是原书内容的维护位置。这里说明迁移关系，不重写原书规则。

| 原书规则 | 本技能借用的阅读原则 | 迁移的限制 |
| --- | --- | --- |
| F05 | 先初步了解，再决定投入 | 查看 README 与目录不是验证项目功能 |
| A03–A04 | 理解部分关系与作者的问题 | 代码调用链和用户的新需求不是作者书中提纲 |
| A05 | 在上下文中确认关键术语 | API 名称和编程语义还须由当前实现与依赖确定 |
| A19 | 将作者提供的结构指引放回材料核实 | 文档与代码可能属于不同版本，冲突须保留双方证据 |
| A24–A25 | 用改述与实例检验理解 | 预测代码输出、修改参数和教学练习是应用设计 |

原书方法出处需要核对时，使用共享 [来源指南](../../how-to-read-a-book/references/source-guide.md) 和 [证据索引](../../how-to-read-a-book/references/evidence.json)，按原规则 ID 查询。GitHub 学习中的新步骤不得伪造原书章节、页码或证据 ID。

## 新增应用程序

仓库类型区分、提交与版本定位、README 与源码对照、调用路径、依赖与环境、命令检查、最小示例、运行记录及教学练习均是本套件为了 GitHub 学习增加的应用程序。这些程序接受自身的行为验证，不受原书证据索引自动背书。

阅读与推演支持对已有材料的解释；执行记录支持某次具体运行的结果；用户回答与动手结果支持对应理解能力的判断。三类证据不能互相替代，局部结果也不能自动推广到整个项目或科研结论。

## 模块之间的责任

原书规则与通用笔记结构由 `how-to-read-a-book` 维护，本模块直接读取需要的文件。论文问题、方法、实验与相关文献比较由 `research-reading` 主导；本模块只提供目标所需的实现依据与运行结果。科研主流程请求实现证据时，返回该主流程，不再次路由。

本模块的默认目标是理解与学习。修复、审查、部署及仓库管理具有各自的目标；只有用户实际提出相关任务时才进入相应工作，不从阅读一本教程自动派生。
