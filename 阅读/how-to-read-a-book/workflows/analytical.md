# 单书分析阅读

执行下列分析动作前，读取 [阅读目标与基础](../rules/reading-core.md) 与 [分析阅读](../rules/analysis.md) 的规则正文及边界；下面的动作概述不能替代它们。同版本完整内容已在当前上下文时直接复用。依据 routing.yaml 的书类条件，加载当前作品对应的一份书类规则；混合类仅加读实际影响判断的部分。想象文学改走文学流程。

1. 若整体架构尚不清楚，先按 [检视规则](../rules/inspection.md) 建立轮廓。
2. 依原书第一阶段，确认类别，用简短文字表达全书统一性，解释主要部分的组织关系，指出作者要解决的问题。
3. 依第二阶段，辨认关键词在文中的特定意义；找重要句子，用自己的话重述主旨；连接理由、前提和结论，识别假设与论证种类；说明哪些问题解决、未解决，作者是否知道遗漏。
4. 依第三阶段，先确认理解，再提出赞同、反对或暂缓判断及理由。按规则区分知识不足、知识错误、推理问题和分析不完整，批评须落到影响结论的具体内容。
5. 回答作品对读者的意义，并按书类处理：实用书涉及目标与行动条件；不能给所有书强加行动清单。

需要字典、参考书、导读、经验或相关书辅助时，读 [辅助阅读](../rules/reading-aids.md)。需要组织笔记时读 [笔记与练习](../rules/notes-and-practice.md)。

交付应覆盖当前请求需要的四问，并给出关键解释或评价的作品位置。四问和三阶段是理解关系，不要求固定重复通读次数，不要求每次输出同样长的模板。

核对：用自己的语言解释关键主旨并给出适用的例子，检查论据是否真支持结论；只读片段时仅作局部分析。用户要自检则进入 [理解核对](understanding.md)。

生成、更新或核对笔记时，再按 [公共笔记约定](../references/note-contract.md) 组织来源、范围、解释与评价。
