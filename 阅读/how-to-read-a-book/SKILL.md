# 如何阅读一本书

本技能维护原书阅读规则与证据，执行普通书籍阅读，并为科研阅读、GitHub 学习提供共享依据。详细规则按任务加载。套件边界、安装和更新见 [安装与维护](INSTALL.md)，成员及版本见 [bundle.json](bundle.json)。

## 选择当前任务

从对话获取材料、目的、已读范围和时间；已有信息足够就开始。读取 [routing.yaml](routing.yaml)，选一条主流程。先判断专业论文或 GitHub 学习，再判断普通读书的目的；做笔记不改变材料所属的主流程。

进入流程后，先补齐当前步骤明文要求读取的规则与引用文件，再依其执行；流程摘要或规则编号不能代替规则正文。当前上下文中已完整读取、版本一致的内容直接复用；条件引用只在条件满足时加载。

研究问题同时涉及论文与代码时，科研模块主导，GitHub 模块只承担具体实现任务。子技能直接读取共享文件，不重新进入本入口。需要改路时以用户目标或材料变化为依据。

## 在对话中使用

以下为 AI 对话的应用约定，原书规则的忠实意译只由 `rules/` 维护：

- 先实际打开正文、目录或片段，标清范围。只有书名时可解释读法；未经读取不能声称完成检视、通读或准确概括全书。
- 方法依据用本技能规则 ID；作品解释用该作品的章、节、页或片段定位。二者分别记录，不凭记忆补造页码。
- 区分作者明确表达、解释性推断和读者评价。材料不足时保留未确定；未查看与材料未报告分别说明。
- 用户要带读时，先解释当前材料允许说明的内容，再围绕难点邀请其复述或举例。用户要直接分析或笔记时直接交付。
- 用户要带读时，默认在每个已完成的阅读单元后同步整理阶段性笔记；笔记注明作品版本、实际已读范围、作者主张、文本推断、读者评价和用户理解证据。没有用户复述或实践证据时，明确标注“用户理解尚未检验”；用户指定其他格式或要求只讨论时，按用户要求处理。
- 助手写出的笔记和完成的运行不能证明用户已理解。能力判断需要用户自己的解释或实践证据。
- 原书外的方法、科研检查、代码教学和笔记格式须标作应用扩展，不加进原书规则或冒充原书原句。

## 完成阅读与笔记

按主流程核对当前材料能支持的判断。生成、更新或核对笔记时，读取 [公共笔记约定](references/note-contract.md) 和 [笔记与练习](rules/notes-and-practice.md) 的 F11、F12，笔记的深度随阅读目的与实际范围变化。

局部阅读只交付局部结论；检视的初步印象保留初步性质。是否需要重读取决于剩余问题和用户目标，篇幅与模板均按任务选择。

解释方法来源、核对或修改原书规则时，读取 [来源指南](references/source-guide.md)；每条规则的段落、PDF 页序和短摘见 [evidence.json](references/evidence.json)。原文核对、历史审查和本次套件验证的范围见 [验证记录](references/validation.md)。
